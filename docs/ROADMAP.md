# Extension roadmap

## Finish release verification

First run the frontend install/build/type tests, Typst round trips, real GitHub OAuth login, PostgreSQL migration/owner-isolation checks and browser E2E flow in a dependency-enabled environment. Address the dependency audit, freeze lockfiles and review privacy/security/accessibility. Do not label the package production-ready solely because backend unit tests pass.

## Connect the real Project Gallery

Obtain a stable company-owned API, authenticated learner identity, artefact snapshot/version, reviewer identity and assessment scope. Distinguish observed file contents, user-attributed contribution, and independently reviewed capability. Do not automatically convert hosting or a README statement into a verified achievement.

A future source fact should have: learner ID, artefact ID, immutable version/hash, a precise claim, its source range, inspection method, review method if any, issue time and issuer. Verify the issuer/snapshot before admitting the fact to a separate project-source scope. Never move a repository fact into an employer's role. User permission and visibility rules must be enforced before serving evidence.

There is intentionally no fabricated live Gallery connector or evidence badge in this release.

## Extend scoring without losing reproducibility

Add reviewed aliases and stable IDs to a new versioned taxonomy file. Keep old versions available for historical recomputation; do not overwrite an old version with different content. Add regression cases for ambiguity, negation, compound requirements, local terminology and unknown requirements. The starter records a taxonomy content hash; a production history service should archive the dictionary/version used by each assessment.

Do not use a model-generated percentage. A larger dictionary does not turn mention coverage into proficiency or an employer's internal score.

## Extend rewriting safely

Add each permitted transformation explicitly, with equivalence assumptions, source references and adversarial tests. An entity diff alone is insufficient: ownership, attribution, qualifiers and relations can change while every token still appears elsewhere in the input. Broader free-form model rewrites remain proposals, not approved content.

## Product extensions not included

Structured role-entry forms; production multilingual/RTL templates; DOCX with round-trip checks; guarded cover letters and LinkedIn About; private-repository inspection; hosted portfolio pages; role-specific templates; reviewer/admin workflows; stronger upload sandboxes; distributed jobs/rate limits; accessibility audit; verified parental-consent flow.

Keep unrestricted generated prose and unreviewed artefact claims out of the submitted resume while these features are developed.
